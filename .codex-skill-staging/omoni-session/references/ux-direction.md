# OMONI UX Direction

Use this file when a task affects product feel, interaction design, or UI decisions.

## Product tone

- Apple-like, but with OMO personality.
- Calm, focused, premium, and intentional.
- Native-feeling over flashy.
- Clarity over cleverness.

## Interaction principles

- A screen should open already making sense.
- Avoid startup turbulence: too many tasks, repairs, focus jumps, or sudden state corrections.
- Editing flows should feel stable and confident, not patched together.
- Motion should support comprehension, not call attention to itself.
- Inputs and money-related flows should feel trustworthy and precise.

## Quality bar

- No demo-grade shortcuts.
- No "works now, clean later" fixes in user-facing flows.
- If a flow feels confusing in code, it often feels confusing in the product too.

## For copy and UI wording

- Prefer short, calm, direct language.
- Avoid enterprise jargon.
- Favor labels that feel native on iOS.
